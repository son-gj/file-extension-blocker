# 파일 확장자 차단 (File Extension Blocker)

파일 확장자에 따라 특정 형식의 파일을 첨부하거나 전송하지 못하도록 제한하는 관리 도구입니다.

## 주요 기능
- **고정 확장자 관리**: 차단 빈도가 높은 7가지 확장자(bat, cmd, com, cpl, exe, scr, js)를 관리합니다.
- **커스텀 확장자 추가**: 최대 200개까지 사용자가 직접 확장자를 등록할 수 있습니다.
- **실시간 상태 유지**: 체크박스 토글 및 커스텀 확장자 추가/삭제 시 DB에 즉시 반영되어 새로고침 후에도 상태가 유지됩니다.

## 기술 스택
- **Backend**: Java 21, Spring Boot 3.x, Spring Data JPA
- **Frontend**: Thymeleaf, JavaScript (Vanilla JS), CSS
- **Database**: H2 Database (In-Memory)

## 과제 수행 시 주요 고려 사항

### 1. 데이터 정합성 및 중복 방지
- **대소문자 통합 처리**: 사용자가 `sh`, `SH`, `Sh` 등 다양한 형태로 입력하더라도 중복으로 인식하도록 모든 입력을 소문자(`toLowerCase()`)로 정규화하여 저장했습니다.
- **영문 전용 유효성 검증**: 한글, 숫자, 특수문자 등록을 방지하기 위해 정규표현식(`^[a-zA-Z]+$`)을 적용하여 보안성과 정합성을 높였습니다.

### 2. 사용자 경험(UX) 및 인터페이스
- **비동기 통신 (REST API)**: 전체 페이지 새로고침 없이 REST API 통신을 통해 부분적인 상태 변경이 가능하도록 구현하여 매끄러운 사용감을 제공합니다.
- **예외 상황 피드백**: 커스텀 확장자가 200개를 초과하거나 중복된 경우, 브라우저 알림(`alert`)을 통해 명확한 사유를 사용자에게 즉각 전달합니다.

### 3. 보안성 강화
- **XSS 공격 방지**: Thymeleaf의 `data-*` 속성을 활용하여 자바스크립트 이벤트 핸들러에 서버 변수가 직접 노출되지 않도록 설계하여 스크립트 인젝션 위험을 차단했습니다.
- **실행 파일 차단 의도 반영**: 보안상 위험이 큰 실행 파일(`exe`, `sh` 등)의 업로드를 제한하려는 과제 본연의 목적을 충실히 이행했습니다.

### 4. 초기 데이터 구성
- **서버 기동 시 자동 세팅**: `FileExtensionBlockerApplication.java`에서 `CommandLineRunner`를 통해 고정 확장자 7종을 DB에 자동 초기화하여 별도의 SQL 실행 없이 바로 테스트가 가능합니다.

### 5. 개발 환경 설정
- **H2 In-Memory DB를 사용한 이유**:
  * **편의성 및 즉시성**: 별도의 데이터베이스 설치나 복잡한 설정 없이도 프로젝트를 내려받아 즉시 실행하고 테스트할 수 있는 환경을 제공하기 위해 선택했습니다.
  * **검토 효율성**: 채용 담당자나 면접관이 과제 코드를 검토할 때, application.properties 설정만으로도 즉시 동작하는 환경을 구축하는 것이 중요하다고 판단했습니다.
  * **운영 환경 고려**: 현재는 인메모리 방식을 사용하고 있으나, 실제 서비스 운영 환경에서는 application.properties의 설정 변경만으로 MySQL, PostgreSQL 등 외부 영속성 DB로 쉽게 전환할 수 있도록 Spring Data JPA를 활용하여 데이터 접근 계층을 추상화했습니다.
- **H2 In-Memory DB 관리**: `hibernate.ddl-auto=update` 설정을 통해 개발 효율성을 높였으며, H2 Console을 활성화하여 데이터 실시간 검증이 가능하도록 설정했습니다.
### 6. DOCKER를 이용한 배포
- **환경 독립성**: OS나 Java 버전 차이로 인한 "내 컴퓨터에선 되는데 서버에선 안 되는" 문제를 원천 차단했습니다.
- **운영 효율**: 도커의 멀티 스테이지 빌드를 통해 실행 환경 최적화와 이미지 경량화를 실현했습니다.

## 서비스 사용 방법 (User Guide)

파일 업로드 보안을 위해 특정 확장자를 차단하는 화면입니다. 

### 1. 고정 확장자 차단 설정

* **목적**: 보안상 위험이 큰 실행 파일 등의 차단 여부를 결정합니다. 
* **방법**:
  * 화면 상단의 **고정 확장자** 리스트(bat, cmd 등)에서 차단하고 싶은 항목의 체크박스를 클릭합니다. 
  * 체크 시 즉시 DB에 저장되며, 페이지를 새로고침해도 차단 상태가 유지됩니다. 


### 2. 커스텀 확장자 추가

* **목적**: 고정 리스트 외에 관리자가 개별적으로 차단할 확장자를 등록합니다. 
* **방법**:
  * **확장자 입력**창에 추가할 확장자명을 입력합니다 (최대 20자까지 입력 가능). 
  * **+추가** 버튼을 누르면 아래 목록에 즉시 반영됩니다. 
* **제약 사항**:
  * 영문 대/소문자만 입력 가능하며, 한글이나 숫자는 차단됩니다.
  * 이미 등록된 확장자는 중복 등록되지 않습니다. 
  * 커스텀 확장자는 최대 **200개**까지만 등록할 수 있습니다.
  

### 3. 커스텀 확장자 삭제

* **방법**: 등록된 커스텀 확장자 옆의 **X** 버튼을 클릭하면 즉시 목록에서 제거되며 DB에서도 삭제됩니다.

## 로컬 개발 환경 실행 방법

1. **프로젝트 빌드**: `Gradle`을 이용해 프로젝트를 빌드합니다.
2. **서버 실행**: `FileExtensionBlockerApplication.java`를 실행합니다 (8080 포트).
3. **접속 주소**: 브라우저에서 `http://localhost:8080`으로 접속합니다. 
4. **DB 확인 (선택)**: `http://localhost:8080/h2-console`에서 실시간 데이터를 확인할 수 있습니다.
