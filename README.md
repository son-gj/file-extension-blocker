# [과제 제출] 파일 확장자 차단 관리 시스템 (File Extension Blocker)

## 1. 프로젝트 개요 및 URL

* **성명**: 손갑주
* **GitHub 저장소**: https://github.com/son-gj/file-extension-blocker
* **배포 사이트 URL**: https://file-extension-blocker-49vn.onrender.com
> **참고**: Render 프리 티어 특성상, 15분간 접속이 없으면 서버가 휴면 상태로 전환됩니다. 첫 접속 시 서버가 깨어나는 데 약 30~50초 정도 소요될 수 있습니다.



---

## 2. 기술 스택 (Tech Stack)

* **Backend**: Java 21, Spring Boot 3.5.10
* **Frontend**: Thymeleaf, JavaScript (Vanilla JS), CSS
* **Database**: H2 Database (In-Memory)
* **ORM**: Spring Data JPA (Hibernate)
* **DevOps**: Docker (Multi-stage Build), Render

---

## 3. 핵심 구현 기능 및 고려 사항

### ① 데이터 정합성 및 유효성 검증

* **대소문자 통합 처리**: `sh`, `SH` 등 입력 형태에 상관없이 동일 확장자로 인식하도록 모든 입력값을 소문자(`toLowerCase()`)로 정규화하여 중복 체크를 수행합니다.
* **영문 전용 검증**: 정규표현식(`^[a-zA-Z]+$`)을 적용하여 한글, 숫자, 특수문자의 등록을 원천 차단했습니다.
* **커스텀 제한**: 최대 20자 길이 제한 및 최대 200개 등록 제한 요건을 충실히 이행했습니다.

### ② 사용자 경험(UX) 및 인터페이스

* **REST API 비동기 통신**: 페이지 새로고침 없이 체크박스 토글 및 확장자 추가/삭제가 즉각 반영되어 매끄러운 사용감을 제공합니다.
* **사용자 피드백**: 중복 등록이나 개수 초과 시 브라우저 알림(`alert`)을 통해 명확한 예외 사유를 전달합니다.

### ③ 보안성 및 운영 효율

* **XSS 방어**: Thymeleaf의 `data-*` 속성을 활용해 자바스크립트 이벤트 핸들러에 서버 변수가 직접 노출되는 것을 방지, 스크립트 인젝션 위험을 차단했습니다.
* **Docker 환경 구축**: OS나 Java 버전 차이로 인한 환경 문제를 방지하기 위해 컨테이너화하였으며, **멀티 스테이지 빌드**를 통해 이미지 크기를 최적화했습니다.

### ④ 데이터베이스 설계 의도

* **H2 In-Memory DB 사용 이유**: 별도의 DB 설치 없이 즉시 실행 가능한 환경을 제공하여 검토자의 효율성을 높이고자 했습니다.
* **확장성 확보**: Spring Data JPA를 통해 데이터 접근 계층을 추상화하여, 향후 설정 변경만으로 MySQL 등 외부 영속성 DB로 즉시 전환이 가능하도록 설계했습니다.
* **초기화 자동화**: `CommandLineRunner`를 통해 서버 기동 시 고정 확장자 7종을 자동 세팅하여 테스트 편의성을 극대화했습니다.

## 4. 서비스 사용 방법 (Manual)

### 1) 고정 확장자 설정

* 상단 리스트에서 체크박스를 클릭하면 즉시 DB에 반영되어 새로고침 후에도 상태가 유지됩니다.

### 2) 커스텀 확장자 추가

* 입력창에 확장자 입력 후 `+추가` 버튼 클릭 (최대 200개).
* 영문만 가능하며 중복 등록은 차단됩니다.

### 3) 커스텀 확장자 삭제

* 등록된 태그 옆의 `X` 버튼을 클릭하여 실시간으로 삭제할 수 있습니다.
